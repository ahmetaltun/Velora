# Privacy Policy for Velora

Velora is engineered from the ground up as a private, local-first utility for macOS. Your data, files, directory structures, and system configurations are your personal property. Velora is designed to never collect, transmit, or monetize your private information.

---

## Core Principles

- **Local Execution**: All indexing, directory traversals, pattern searches, hashing, and threat scans execute entirely on your Mac.
- **Zero Telemetry**: Velora contains no analytics frameworks, tracking pixels, crash reporting SDKs, or advertising identifiers.
- **Zero Third-Party Data Sharing**: No data inspected or generated by Velora is ever sent to third parties or remote cloud servers.
- **Auditable Open Source**: The complete codebase is open source and verifiable under the MIT License.

---

## Information Processed Locally

### Filesystem Metadata and Contents

To calculate directory sizes, render sunburst visualizations, identify duplicate files, and locate developer caches, Velora reads filesystem metadata (such as paths, file sizes, modification timestamps, and permissions) directly from your storage volumes.

- File metadata is loaded into volatile memory while the application is active.
- For accelerated subsequent launches, Velora can persist an index snapshot (`catalog.bin`) to your local user directory:
  `~/Library/Application Support/dev.ahmetaltun.Velora/catalog.bin`
- This index file never leaves your local computer.

### Duplicate Hashing and Threat Detection

- Duplicate detection computes cryptographic hashes (Blake3) locally on candidate files to match byte-for-byte identical content.
- Malware and persistence inspection inspects Auto-Start Extension Points (LaunchAgents, LaunchDaemons, Login Items) and binary signatures locally against known signature databases.
- At no point are your file hashes, names, or file contents uploaded to external threat intelligence feeds or online scanners.

---

## Network Communication

Velora performs only one optional network operation: checking for application updates.

### Sparkle 2 Software Updates

Velora integrates the Sparkle 2 framework to notify you of newer application releases.
- **Mechanism**: The updater sends a standard HTTPS request to fetch the signed XML appcast feed (`appcast.xml`) hosted on GitHub Releases.
- **Data Sent**: The update check transmits standard HTTP request headers along with your current Velora version string and macOS OS version (required to determine compatible update binaries). No personal identifiers, IP addresses, usernames, or filesystem metadata are logged or tracked.
- **Control**: You can disable automatic update checking at any time in Velora's application settings or by declining update prompts.

---

## macOS System Permissions

Velora may request specific macOS permissions to function correctly:

- **Full Disk Access**: Required to index system-level directories, user Library caches, and Xcode developer storage. macOS Full Disk Access is utilized exclusively to read file metadata for local analysis.
- **Trash Operations**: Velora uses standard macOS system APIs (`NSWorkspace.shared.recycle`) to move queued files to the macOS system Trash. Velora does not permanently delete files without moving them to the Trash, ensuring you retain the ability to restore items.

---

## Data Retention and Deletion

- All application data, cached indexes, and settings can be deleted at any time by removing the application bundle and its corresponding local application support directory (`~/Library/Application Support/dev.ahmetaltun.Velora`).
- Quarantined items reside exclusively in your local quarantine directory and can be permanently removed or restored at your discretion.
